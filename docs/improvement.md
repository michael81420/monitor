# 每週改善流程

`improve(store, config, runner=None)` 讀取最新系統檢查報告與運作紀錄，請 improver 提出有依據的完整檔案替換。缺少帳號、權限或來源資料時，不能用假資料或修改規則假裝問題已修正。

## 寫入範圍

候選只可修改 `monitorbot` 下第一層 Python 檔案、新增 `tests` 下第一層 Python 測試，以及 `skills/monitorbot/SKILL.md`。既有測試是不可修改的基準。`improve.py`、`agents.py`、`__init__.py`、`__main__.py`、`install.py` 與 `menubar.py` 是受保護的驗證、編譯與啟動入口，不接受自動修改。

設定、正式資料、憑證、其他路徑與符號連結都不在修改範圍。候選程式樹只包含程式、測試與指定 skill，不複製正式 `.monitor` 目錄。

## 驗證與套用

1. 保存提案、理由、紀錄索引與 diff。同一份程式變更使用固定雜湊識別，更改說明文字不會形成新嘗試。
2. 獨立 change reviewer 先看原始問題與程式，列出關注點與約束。這次呼叫不提供候選方案。
3. 使用 SQLite backup 備份本機資料庫，實際恢復到另一份資料庫，檢查完整性與資料一致。
4. 在 macOS `sandbox-exec` 下驗證禁止網路、讀取外部測試檔與寫入外部路徑。邊界探測失敗就阻擋自動套用。
5. 在同一類 OS sandbox 內，執行變更前的唯讀基準測試與新增的候選測試。候選程式碼與基準均不可寫入，暫存資料只可寫入指定測試目錄。
6. 在隔離的資料副本上執行候選 Store 初始化。父程序使用自己的唯讀 SQLite 連線核對原表、原欄位與原紀錄，並檢查完整性，不採信候選子程序自稱的成功結果。無法保留舊資料時不能自動套用。
7. change reviewer 再讀取 diff、先前獨立評估及實際驗證證據。拒絕、測試失敗或資料不保留時，保留問題與失敗原因。
8. 確認原始程式、基準與正式資料在驗證期間未變動，才逐檔原子替換。保留原始版本、資料庫備份及回復紀錄。檔案替換失敗會回復已替換檔案。

程式不使用普通 subprocess 測試作為 OS 隔離的替代。非 macOS、缺少 `sandbox-exec` 或 OS 不允許建立 sandbox 時，回傳 `blocked`。單元測試中的程序替身只驗證控制流程，不代表實際隔離成功。

## 失敗與中斷

問題保存在 `improvement_issues`，區分 `discovered`、`in_progress` 與 `verified`。每次嘗試另記錄結果。相同證據已處理時略過，相同失敗提案不重複驗證。沒有可證明的新方法時，問題保留，不宣稱修正。

套用前建立持久回復紀錄。CLI 在載入可變更模組之前回復中斷的檔案更新；如果檔案已被使用者另行修改，停止自動回復，避免覆蓋新修改。自動流程不使用舊資料庫備份覆寫後續使用者資料。

## 設定與產物

`improvement.enabled` 控制流程是否執行。`improvement.auto_apply` 控制通過驗證後是否套用，預設為啟用。關閉自動套用時仍可保存已驗證提案。

產物位於資料目錄的 `improvements/<proposal_hash>`，包括 `proposal.json`、`change.diff`、`database-backup.sqlite3`，以及完成對應階段後的 `verification.json`、`review.json` 與 `rollback.json`。預設永久保存，目前的資料庫清理指令不會自動刪除這些檔案。

成功改善只記錄運作紀錄，不逐項跳彈窗。需要使用者處理的阻礙由每日確認與系統檢查流程呈現。

## 驗證限制

測試會固定 unittest 核心參照、檢查核心是否被替換，並用必敗案例確認失敗仍會被記錄。這已擋住實際重現的測試偽成功，但不構成對任意惡意 Python 或蓄意條件分支的形式證明。獨立審查仍須檢查變更理由與實作。

資料初始化保留檢查不代表所有未來操作都經形式驗證。涉及不可證明的遷移就停止自動套用。

多檔修改以每個檔案的原子替換與持久回復紀錄保護，不具備整個程式目錄同時切換的原子性。執行中的 Python 程序仍使用已載入的模組，新程序才會載入新檔案。受保護的 CLI 入口在下次啟動時處理回復。
