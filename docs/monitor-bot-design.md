# Monitor bot 設計草案

本文件是已確認的訪談需求基線。原提案預設已由使用者確認；實作與能力限制見 [README](../README.md)，實際查核見 [驗證紀錄](verification.md)。

## 目標與第一版範圍

系統在本機背景記錄工作活動，追蹤任務，累積工作知識，並自動產生週報。優先處理漏事與工作回溯。第一版在單台 Mac 執行，來源擷取與通知的設計須容許替換為 Windows 實作。

第一版來源包含 Teams、Outlook、Excel、Word、PowerPoint、Chrome，以及使用者與 AI 的對話。Gerrit 暫不接入。來源是否可用須逐一驗證，未接通或未支援的來源明確顯示狀態，不以模擬資料宣稱已接通。

## 活動範圍與擷取

- 預設涵蓋整台電腦的工作活動，不主動掃描整顆硬碟。
- 每種來源各自設定納入與排除規則。支援全機工作活動與限定工作範圍。
- Office 文件預設涵蓋實際使用的文件，可依路徑與檔名排除。
- Teams 可依帳號、團隊、頻道、聊天室與參與者過濾。
- Outlook 可依帳號、資料夾、寄件者、網域與主旨過濾。
- Chrome 可依 profile、網域與網址過濾。AI 對話可依工具、帳號、對話與專案過濾。
- 排除規則優先。來源資訊過濾在讀取內文前處理，內文條件另行標示。
- 第一版提供固定條件與 Python 操作工具，支援預覽規則影響。
- 密碼與驗證碼輸入、無痕瀏覽排除。不記錄所有按鍵。
- 不做背景螢幕擷取。agent 主動查閱網頁或簡報時，可使用少量截圖輔助理解。

信件與聊天即使未開啟應用程式，也每小時增量檢查新內容。文件與網頁主要依使用、儲存、送出、引用或手動指定觸發讀取。擷取活動與呼叫模型分開，沒有新內容時不呼叫模型。

啟用時可指定回溯 N 天，預設 0 天。0 天表示不批次匯入歷史，仍可沿新訊息或任務回查舊背景。回查到的舊活動不計為今天的成果。只能回溯來源確實提供的歷史。

## 資料組織與工作知識

查閱結果採巢狀組織，原始來源索引可由多項任務引用。

```text
專案或產品
  任務
    預期成果、責任、期限、下一步
    目前狀態、最新摘要
    判斷歷史、來源索引
  知識主題
    目前做法、支援機制、限制
    適用平台、版本與時間
    提案、決定、實作、驗證的進展
    變更歷史、衝突、來源索引
```

另提供時間、人物、來源與狀態索引。Python 工具先篩選，再提供摘要，需要判斷時才取相關原文。摘要記錄涵蓋的活動位置，避免重複分析或使用過時摘要。

知識跨任務累積，不因任務完成或註銷而消失。新說法保留舊紀錄，明確取代後才更新目前結論。未解衝突保留分歧。回答目前做法時區分提案、已決定、已實作與已驗證。

雲端信件、聊天與文件不另存原文副本。保存可回查的來源識別、討論串或文件位置、時間與可取得的版本資訊。整理後的知識、摘要、任務與判斷歷史保存在本機。來源失效時標示無法核對，不能宣稱重新驗證成功。

允許 agent 讀取本機資料，並將當次分析所需內容提供給其使用的雲端模型。

## 任務規範與狀態

任務透過固定 Python 工具新增與修改，agent 使用對應 skill。工具驗證 JSON 輸入與狀態轉換，所有變更保留歷史。未知欄位明確標記未知，不臆造期限、責任或完成條件。

任務資料涵蓋穩定識別、事項與預期成果、來源索引、責任歸屬、狀態、期限及其依據、下一步、依賴條件、最後實質活動、結束原因與判斷歷史。具體欄位與狀態列舉在實作時定義。

| 情況 | 處理 |
|---|---|
| 明確承諾或指派 | 自動建立與追蹤 |
| 有空研究或靈感 | 也記錄，可適用閒置註銷 |
| 證據支持預期成果已達成 | 自動完成，不要求使用者逐項確認 |
| 完成後出現反證 | 自動重新開啟，保留原判斷 |
| 明確移交責任且不再涉及使用者 | 退出使用者待辦，保留交接原因 |
| 請使用者找人協助或取得資料 | 仍追蹤使用者的交付責任 |
| 他人先完成工作，使用者之後接手 | 等待前置工作，不適用閒置註銷 |
| 可選事項，沒有期限或明確承諾 | 30 天沒有實質進展，可經複核註銷 |
| 尚未明確歸屬使用者 | 30 天沒有實質進展，可經複核註銷，原因為責任未確認且無後續 |

已承諾或被指派的任務，不因缺少期限而適用閒置註銷。等待兩個月後進行 IT 驗證的任務保留，預估開始時間與使用者交付期限分開記錄。

新增要求、討論進展、相關產出、期限與責任變更算實質活動。agent 讀取、重寫摘要、產生報告與無進展的再次提及不重設閒置時間。來源中斷或覆蓋不足時暫停受影響事項的閒置註銷。

排除來源不刪除既有知識。任務所有有效依據來源皆被排除時，退出待辦並保留原因。仍有未排除的有效來源則持續追蹤。另支援直接排除任務或主題。恢復追蹤必須有新的有效且未排除來源。使用者直接排除的任務或主題須先解除排除，agent 不得繞過規則自動恢復。

## 每日確認與待處理清單

預設週一至週五 09:30 顯示，頻率與時間可調整。未使用電腦時延至工作時間內下次使用，不連續補彈多天通知。

每日確認以 10 題為基準，有積欠時可擴大到 20 題，上限可調整。所有問題先提供選項、必要背景與建議答案，選項不適用時可自由填寫。不把未回答視為同意，也不當天反覆彈窗。

每次顯示前重新取得最新進展。已解決、已轉交、已不相關的問題撤下，其餘重新排序與改寫。新舊問題一起依影響排序，不直接重播昨日題目。沒有需要確認的問題就不彈詢問視窗。

明確選擇以後同類都如此處理時，建立限定範圍規則。單次回答先累積偏好，多次一致後才自動採用。規則保存來源、適用範圍與例外，可修正與撤回。涉及退出追蹤的判斷仍經獨立複核。

每日清單分為輪到使用者與等待他人。前者依已逾期、即將到期、阻擋其他工作、其他可執行事項排序。後者依超過前置工作預估時間、影響使用者期限、一般等待排序。靈感與可選研究放在後面，允許手動調整重要性。

每項顯示下一步、目前負責人、期限依據與最近進展。前置工作超時與使用者交付逾期分開呈現。

手動新增採最簡單的一句話入口，先可靠保存再分析，不要求完整填表。第一版具體介面待確認，避免先投入完整桌面 UI。

## 背景程式與 agent 分工

固定程式負責排程、蒐集、去重、索引、格式驗證、保存與資料操作。需要時才啟動 CLI agent，不讓每個 agent 持續佔用常駐程序。

| 角色 | 責任 |
|---|---|
| 較輕量的處理 agent | 分類、摘要、找候選任務 |
| 追蹤 agent | 理解承諾、責任、期限、完成條件，提出任務變更 |
| 獨立審核 agent | 複核完成、轉交、註銷與合併 |
| 報告 agent | 整理週報，衝突交回追蹤 agent |
| 改善 agent | 找出重複問題，提出與驗證改善 |
| 獨立變更審核 agent | 檢查流程與程式修改及驗證結果 |

CLI 後端可替換，沿用既有登入，不另要求 API Key。各角色使用獨立上下文，可依能力配置後端與模型。審核 agent 先讀任務條件與原始證據自行判斷，再比較提案。異議交回補證據，不以反覆互相說服代替驗證。

不另要求模型 API Key 不代表來源無須授權。Teams、Outlook 與其他來源仍須具備相應登入與讀取權限，組織限制須另行查核。

CLI 的提示、工具結果與執行日誌也受不另存原文副本的政策約束。接入前以合成內容查核持久化行為，確認能停用或控制原文紀錄。未通過的後端不能用於讀取真實雲端原文，不能只因核心資料庫未存原文就宣稱政策成立。

休眠、關機與登入過期可能暫停處理。恢復後從各來源最後成功位置補查。無法補回的活動標示缺口，清單與報告顯示資料更新時間。第一版不另部署全天在線主機。

## 週報

每週一早上自動整理上一個完整週，產生一份週報檔案，不持續更新本週草稿。報告前先更新追蹤狀態。發現衝突交回追蹤 agent 調整，再繼續整理。

上週活動依事件發生時間歸屬，當前待辦另標示整理時點。本週的新活動不能算成上週成果。上週完成、本週重新開啟時保留兩次事件；若最新證據推翻上週的完成判斷，報告註明更正，不將錯誤判斷當成確定成果。

週報涵蓋完成事項與產出、未完成事項與下一步、等待他人與超時、交接與註銷、來源排除，以及重要決策和新增知識。來源索引可供寫正式週報時回查。

提案：時區採 Asia/Taipei，上一週定義為週一 00:00 至本週一 00:00 前。週報預設週一 09:30 執行，輸出 Markdown。更正時保留版本，依需要可指定期間另產生報告。

## 系統檢查與自動改善

保存運作紀錄、任務判斷歷史、變更與驗證紀錄，另產生每週系統檢查報告。工作週報與系統檢查報告分開。

系統檢查報告供改善 agent 找出來源缺口、錯誤判斷、重複詢問、低效讀取與驗證失敗。報告引用詳細紀錄，不重複複製整份日誌或雲端原文。

改善範圍包含個人規則、提示與 skill、agent 流程、Python 工具與架構。個人規則遵循已確認的學習政策。流程與程式修改在隔離環境驗證，通過獨立審查後自動套用，保留可回復版本。

驗證使用隔離資料，不直接修改正式紀錄。資料格式變更須先驗證備份、遷移與資料恢復，僅回復程式版本不足以通過。不得透過刪改既有驗收案例消除失敗；需求確實變更時另記錄理由與獨立審查結果。

驗證使用固定案例、既有人工確認與實際運作結果。不能僅因另一個 agent 同意就宣稱正確。修改驗證標準本身須另行記錄與審查。固定規則與任務狀態可重播，來源原文已變動的歷史語意判斷標示無法完整重現。

系統問題區分已發現、處理中與已驗證修正。失敗嘗試保留原因與依據，沒有新證據或方法時不重複相同嘗試。成功改善不逐項彈窗，需要使用者補資料、登入或處理阻礙時才進入每日確認。

## 永久保存與清理通道

任務歷史、知識、來源索引、週報與系統紀錄預設永久保存。按日期分檔與壓縮歸檔，平常先讀索引與摘要。一般運作只記必要事件與錯誤，調查時才啟用詳細 debug。

保留定期清理的通道。提案：清理排程預設停用，可先預覽依資料類型與日期選出的項目及影響，使用者明確設定範圍與保存政策後才執行。清理只處理本工具管理的本機資料，不刪除來源郵件、聊天與文件。清理後不能仍宣稱已刪紀錄可供追溯。

## 儲存與操作工具提案

提案：使用 Python 標準庫 SQLite 保存任務、索引、關聯與歷史，報告採檔案保存。JSON 作為固定 Python 工具的輸入與輸出，不以巨大巢狀 JSON 當唯一資料庫。查閱時組成巢狀結果。

agent 經固定工具操作資料。工具負責交易、穩定識別與驗證，避免多個 agent 直接修改資料檔。蒐集位置與已處理事件也保存於本機，重試不重複建立活動、任務或報告。

第一版手動入口提案為 Python 指令的一句話輸入。每日題目與清單需有可操作的本機介面，形式待可行性驗證後選擇，不以終端指令取代已要求的每日彈窗。

## 實作前後的查核項目

- 本機已找到 Chrome 與 agent CLI，未找到原生 Microsoft Office、Teams 與 Outlook 應用程式。網頁版與帳號連接尚未查核。
- Codex 與 Claude CLI 已由 help 與官方文件確認具備非互動與結構化輸出能力，支援沿用既有登入。尚未執行模型任務，未驗證此機登入、額度、背景環境與 Keychain 存取。
- Microsoft 來源的權限與歷史、Office 文件存取、Chrome 活動觸發、AI 對話涵蓋率須實測。
- 模型與各角色映射、token 或使用額度上限尚未指定。沒有新內容時略過，先篩選再取文，記錄實際用量與失敗，避免不受控重試。
- 驗收須包含兩個月等待、責任未確認的註銷、來源排除與多來源任務、來源中斷、反證重開、問題過時撤下，以及週一整理前一完整週。
- 自我修改的套用與回復、資料格式變更的保護、重試去重及清理影響須用實際程式驗證，文件描述不代表已完成。
